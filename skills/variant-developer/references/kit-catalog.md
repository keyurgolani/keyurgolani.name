# @portfolio/kit catalog

> Every export from @portfolio/kit, grouped by topic, with a one-line
> "use this when..." per export. Loaded by the agent before each
> implementation cluster (Phase 2 Wave 2). CI keeps this in sync with
> packages/kit/src/index.ts via sync-checks.mjs (`pnpm check:skills`).

## Source of truth

`packages/kit/src/index.ts` is authoritative for the main barrel; the
sub-path entry points (`@portfolio/kit/<topic>`) are listed in
`packages/kit/package.json` `exports`. This catalog paraphrases.
If they disagree, the source wins.

## Motion (`@portfolio/kit`)

| Export                    | Signature                                       | Use when                                                                        |
| ------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------- |
| `MotionPolicyProvider`    | component `{ policy?: MotionPolicy, children }` | Wrapping a variant's client parts, with `input.presentation.motionPolicy`.      |
| `useMotionPreference`     | `(policy?: MotionPolicy) => 'reduce' \| 'full'` | Reading the resolved motion preference in a client component.                   |
| `useProvidedMotionPolicy` | `() => MotionPolicy`                            | Reading the policy the nearest `MotionPolicyProvider` gives, else `respect-os`. |
| `shouldReduceMotion`      | `(policy: MotionPolicy, osReduce) => boolean`   | Synchronous server-side check or non-hook contexts.                             |
| `ResolvedMotion` (type)   | `'reduce' \| 'full'`                            | Annotating motion-aware props.                                                  |

`MotionPolicy` is `respect-os` (the default: follow `prefers-reduced-motion`) or `reduce`. No policy animates past an OS reduce preference. The site's policy reaches a variant as `input.presentation.motionPolicy`, and the host's document boundary carries the motion that renders as `data-motion`, `full`, `reduced`, or `static`, so a stylesheet can reduce CSS motion under it as it does under `prefers-reduced-motion`. A variant wraps its client parts in `MotionPolicyProvider` with it, so every `useMotionPreference()` below reads it. A `policy` given to the hook, or a component's `motionPreference` prop, can only add a `reduce`: neither undoes the site's. The preference says whether motion is allowed, not whether an effect may run now: run the effect on the runtime below.

## Display modes and tokens

The kit has no theme module and no tokens of its own. Display modes, colors, type, and the rest are the appearance axes' (#19): the host renders each page's document boundary from the published selection and the visitor's choice, the packs set the `--color-*`, `--ui-*`, and `--type-*` properties on it, and the visitor's appearance control renders in the `VisitorControlSlot`. A variant reads those properties from CSS and renders no theme toggle.

## The manifest and the render input (`@portfolio/variant-contract`)

The kit has no manifest types any more. `VariantManifest`, `VariantRenderInput`, `validateManifest`, and `buildRenderInput` are `@portfolio/variant-contract`'s; `references/manifest-contract.md` describes every field. A section kind without a bespoke renderer renders through `renderSection`'s shared renderer, below, so there's no fallback component to route to.

## Shared section renderers (`@portfolio/kit/sections`)

> No client modules, and nothing reads the clock, randomness, or the network, so the server, #7's preview frame, and #9's browser render give the same markup. Styling is classes in `@portfolio/kit/sections/styles.css`, under `[data-variant]`, for layout alone, inside `:where()` so any rule of yours for the same element wins. It's opt-in by class: each rule keys on a kit part's own `pf-` class, or an element inside one, never on how the frame was rendered, so a part you place in your own markup keeps its layout. The one exception is the 3rem gap a shared frame has always had, which `pf-stack` on an element of yours replaces with the section rhythm. Its lengths come from the platform's scales, and running text keeps the body measure, at most 68ch. A section of figures alone is a plain `dl.pf-stats`; `pf-stats--leaders` on it or an ancestor makes it a ledger with dotted leaders, which only the fallback uses: give your figures a form of your own. Every rule weighs nothing and counts against your css budget (`apps/web/scripts/variant-css-budgets.test.ts`). Blank text renders as nothing, and so does a section with nothing public. A section in a language that runs the other way from the portfolio gets a `dir`. Every text node is the owner's, formatted from the owner's data, a snapshot's value with its date, or one of #10's fixed labels: no default heading or alt text, and a link the owner gave no label shows its host as written, adding the shortest part of its path or query that tells it from a sibling's on the same host, never a word the kit adds or a whole URL. A host label is a fallback, not a name: label links in your own vocabulary (Slides, Recording, Episode) where you render them. An image is a placement of a media asset, its alt the placement's, else the asset's, and a decorative one has none. Until it has a rendition (#10's second slice), it renders as a box labeled `Image unavailable`, keeping its caption and credit, and a decorative one renders nothing. The signature work's cover loads at once, and every other image lazily. A record's id is its anchor on the first visible section that lists it.

| `tint`     | `(color, t) => string`                 | A highlight: the palette's own colour lightened toward white by `t`, never a colour of its own.                                  |
| `shade`    | `(color, t) => string`                 | A shadow: the palette's own colour darkened toward black by `t`.                                                                 |
| `Box`      | component, `{ x, y, w, h, fill, rx? }` | A rectangle in the drawing, rounded when `rx` is given.                                                                          |
| `Headline` | component                              | A headline at thumbnail size: a solid bar at the headline's x-height, since a thumbnail sets no text a reader would try to read. |
